# MiniBank on AWS – Phase 1: Foundation (runbook)

## What this builds
| File | Creates |
|---|---|
| `network.tf` | VPC 10.0.0.0/16, 2 public + 2 private subnets in 2 AZs, internet gateway, route tables |
| `security.tf` | `web-sg` (HTTP 80 from internet, no SSH) and `db-sg` (3306 only from `web-sg`) |
| `compute.tf` | EC2 t3.micro (Amazon Linux 2023 + nginx), IAM role for SSM + S3 read, IMDSv2, encrypted disk |
| `database.tf` | RDS MySQL db.t3.micro in private subnets, encrypted, 7-day backups, password in Secrets Manager |
| `storage.tf` | Private, encrypted, versioned S3 bucket + a test file |
| `budget.tf` | $5 monthly budget, email alerts at 80% actual / 100% forecast |
| `outputs.tf` | Website URL, SSM connect command, DB endpoint, bucket name |

About 25 resources. RDS takes ~10 minutes to create, so `apply` takes ~12–15 minutes.

## Cost (old account = no free tier)
About **$0.04 per hour** while running (EC2 + RDS + public IP + secret). Destroy after every session.

## One-time setup (Windows)
1. Unzip this folder to `C:\minibank\phase1`.
2. Copy `terraform.tfvars.example` to `terraform.tfvars` and put your real email in it.
3. Install the **Session Manager plugin** (needed for `aws ssm start-session`):
   https://s3.amazonaws.com/session-manager-downloads/plugin/latest/windows/SessionManagerPluginSetup.exe
   Check: `session-manager-plugin` → should print a "successfully installed" message.

## Deploy
Open PowerShell in `C:\minibank\phase1`:
```
aws sts get-caller-identity      # must end with user/minibank-admin
terraform init                   # downloads the AWS + random providers
terraform fmt                    # tidies formatting
terraform validate               # syntax + reference check
terraform plan -out=phase1.plan  # dry run: read it, expect "Plan: ~25 to add"
terraform apply phase1.plan      # builds it
terraform output                 # shows URL, instance ID, DB endpoint
```

## Test (each is a yes/no check)
| # | Test | Command / action | Expected |
|---|---|---|---|
| 1 | Website | open `web_url` in a browser (wait 2–3 min after apply) | "MiniBank – Phase 1" page |
| 2 | SSM shell, no SSH | `aws ssm start-session --target <instance_id>` | a `sh-5.2$` prompt |
| 3 | S3 via role | in the SSM shell: `aws s3 cp s3://<assets_bucket>/welcome.txt -` | the welcome text |
| 4 | DB reachable from web | in the SSM shell: `nc -zv <db_endpoint> 3306` | `Connected` |
| 5 | DB NOT public | from your PC: `Test-NetConnection <db_endpoint> -Port 3306` | `TcpTestSucceeded : False` |
| 6 | No SSH port | from your PC: `Test-NetConnection <web public DNS> -Port 22` | `False` |

Get the DB password (for a real MySQL login in the SSM shell):
```
aws secretsmanager get-secret-value --secret-id <db_secret_arn> --query SecretString --output text
mysql -h <db_endpoint> -u mbadmin -p minibank
```

## Break-it exercises (do these to really learn)
1. Delete the `db_from_web` rule in `security.tf`, apply, repeat test 4 → it fails. Put it back.
2. Remove the `ssm` policy attachment, apply, try test 2 → fails after a few minutes. Why?
3. Run `terraform plan` after changing nothing → "No changes". Change a tag in the console, plan again → Terraform spots the drift.

## Destroy (end of EVERY session)
```
terraform destroy      # type "yes"; takes ~5–10 min because of RDS
```
Then check nothing is left: console → **Resource Groups & Tag Editor** → search tag `Project = minibank` → should be empty.

## Rollback / if something fails
- Apply failed halfway: fix the error and run `terraform apply` again. Terraform continues from where it stopped.
- Want to start clean: `terraform destroy`, then apply again.
- Never delete resources by hand in the console while Terraform manages them; it confuses the state.

## Security choices (interview talking points)
- Database has no public IP and only accepts the web tier's security group, not an IP range.
- No SSH keys and no port 22: shell access is SSM, logged in AWS and controlled by IAM.
- Server permissions come from an IAM role (temporary credentials), never stored keys.
- IMDSv2 required; disks, DB and S3 encrypted; S3 public access blocked.
- DB password generated by AWS and kept in Secrets Manager, not in code or state.
- Budget alarm from day 1.
